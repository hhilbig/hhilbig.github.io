Political Science LLM Benchmark

Hanno Hilbig, University of California, Davis
Results as of November 2026

FiguresHardwareMethods

On this page, I compare the performance and cost of 43 language models – 21 open-weight models as well as 22 commercial models that are accessed through an API – on text classification tasks from political science. I rely on 33 coding tasks drawn from published papers, replication archives and public data sets, covering relevance, stance, tone, events, claims and topics. For each task, every model codes the same 100 texts, and I compare the labels assigned by the model to the labels assigned by human coders in the original data.

Overall, I find that differences between models are small. Claude Opus 5 has the highest mean F1 across tasks (0.714), and the best open-weight model, MiMo V2.6 Flash (FP8), reaches 0.679, which is higher than 11 of the 22 API models. In addition, differences of a few hundredths in the mean F1 often reverse on individual tasks – researchers who want to choose a model should therefore look at the tasks that are closest to their own application.

Not evaluated and excluded models

The models below are not ranked, either because I was not able to run them, in which case they are listed as not evaluated together with the reason, or because a run finished but violated the rules of the benchmark, in which case they are listed as excluded.

The open-weight models on this page are a selection rather than a complete list, and whether I can run a given model depends not only on its size but also on its weight files, its quantization, software support and GPU memory – if a model is missing, this does not say anything about its quality.

  • Mistral Medium 3.5 128B: not evaluated. License eligibility is unresolved; no Hive inference has been submitted.
  • GLM-5.3: not evaluated. No supported single-node Hive runtime was verified for the available quantized weights. The page ranks the API version, which I called through OpenRouter.
  • GLM-5.3-Flash: not evaluated. The SM120 NoPE-MLA runtime issue is open; GPU pilot and fit remain untested.
  • MiniMax M3 NVFP4: not evaluated. The pinned four-GPU Hive pilot failed before inference: the official NVFP4 runtime has no MoE backend that preserves MiniMax M3's SwiGLU clamp on SM120 RTX PRO 6000 Blackwell GPUs. Zero predictions were produced.
  • Kimi K3: not evaluated. Native MXFP4 weight files alone exceed the largest currently listed Hive single-node GPU memory; no multi-node or paid fallback was authorized.
  • Nemotron 3.5 Super VL 120B-A12B: pending. The Hive run had not finished when this release was built.
  • Intern-S2 397B (FP8): pending. The Hive pilot was still waiting for a GPU when this release was built.
  • GPT-OSS 120B (MXFP4): excluded. Job 23393692_0 produced a malformed generated channel in an uncheckpointed task batch without an identifiable item. It cannot be assigned to a frozen text and scored incorrect. Job 23415406 completed a second attempt and retained one separate malformed response with an item ID. Its fully audited 3,400-item output remains exploratory because the first failure cannot be scored under the no-answer-quality-retry rule.

Where the models ran

  • API models: I called each provider's API between 10 and 20 September 2026, using the batch endpoints for OpenAI and Anthropic and sending one request per text for the other providers. Jev 1.13 is a model by TypeSafe that answers by choosing among a fixed set of options, and I called it via OpenRouter's Decisions API. The models added in November ran through OpenRouter between 4 and 6 November 2026, most of them through its batch endpoint.
  • Open-weight models: each model ran on a single NVIDIA RTX PRO 6000 Blackwell GPU (96 GB of memory) on UC Davis's Hive computing cluster, using vLLM 0.26 at temperature 0. The exceptions are Qwen3.8 Flash-Next (two GPUs and a development version of vLLM) and MiMo V2.6 Flash (four GPUs and vLLM 0.32).
  • Settings: reasoning is turned off for all models where this is possible, otherwise it is set to the lowest available level. API models run at their provider's default temperature, except for the two DeepSeek models from September (0.1) and six of the models added in November (0). Since every model coded every text only once, I cannot say how much the answers of a given model vary between runs. All models may return at most 256 tokens, with the exception of Jev 1.13, which returns a label rather than free text, and the November models that cannot turn reasoning off, which may return up to 2,048 tokens (4,096 for Beam 1.0).
  • Not tested: I did not run the API models with extended reasoning, which increases both cost and response time, and I did not run the largest open-weight models (Kimi K3 and MiniMax M3), since these do not run on this hardware. It is possible that the strongest configurations of these models would score higher than the top scores on this page.
Methods and limitations

Sample. For each task, I draw 100 texts by hashing task and item identifiers with the seed 20260910. All models receive the same texts, gold labels and prompts, except for Jev 1.13, which receives the prompt in its provider's choice format (i.e. with a list of the allowed labels for each output field). I only reuse earlier predictions if inputs and settings match exactly.

Scoring. For binary tasks, I use the F1 score for the positive class, for tasks with several binary labels I use the average of the per-label F1 scores, and for categorical tasks with a single label I use macro F1, which gives equal weight to each class. If a class appears neither in the gold labels nor in the predictions, its F1 is 0 by convention, which does not say anything about the model. Unusable answers are counted as incorrect, while infrastructure failures are recorded separately.

Limits. All results are based on 33 tasks. Since most tasks are taken from published data sets, some of the texts or labels may have been part of the training data of the models, which would increase their scores, and I am not able to rule this out. Before using a model at scale, researchers should validate it on labeled examples from their own task.

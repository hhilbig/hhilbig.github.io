Political Science LLM Benchmark

Hanno Hilbig, University of California, Davis
Results as of September 2026

FiguresHardwareMethods

On this page, I compare the performance and cost of 31 language models – 20 open-weight models as well as 11 commercial models that are accessed through an API – on text classification tasks from political science. I rely on 33 coding tasks drawn from published papers, replication archives and public data sets, covering relevance, stance, tone, events, claims and topics. For each task, every model codes the same 100 texts, and I compare the labels assigned by the model to the labels assigned by human coders in the original data.

Overall, I find that differences between models are small. Claude Opus 5 has the highest mean F1 across tasks (0.714), and the best open-weight model, Qwen3.8 Flash-Next (FP8), reaches 0.675, which is higher than four of the 11 API models. In addition, differences of a few hundredths in the mean F1 often reverse on individual tasks – researchers who want to choose a model should therefore look at the tasks that are closest to their own application.

Not evaluated and excluded models

The models below are not ranked. Not evaluated means that I could not run the model, for the reason listed. Excluded means that a run finished but violated the benchmark's rules.

The open-weight models are a selection rather than a complete list. Whether a model runs depends on its weight files, quantization, software support and GPU memory, not only on its size. A missing model therefore says nothing about its quality.

  • Mistral Medium 3.5 128B: not evaluated. License eligibility is unresolved; no Hive inference has been submitted.
  • GLM-5.3: not evaluated. No supported single-node Hive runtime was verified for the available quantized weights.
  • GLM-5.3-Flash: not evaluated. The SM120 NoPE-MLA runtime issue is open; GPU pilot and fit remain untested.
  • MiniMax M3 NVFP4: not evaluated. The pinned four-GPU Hive pilot failed before inference: the official NVFP4 runtime has no MoE backend that preserves MiniMax M3's SwiGLU clamp on SM120 RTX PRO 6000 Blackwell GPUs. Zero predictions were produced.
  • Kimi K3: not evaluated. Native MXFP4 weight files alone exceed the largest currently listed Hive single-node GPU memory; no multi-node or paid fallback was authorized.
  • GPT-OSS 120B (MXFP4): excluded. Job 23393692_0 produced a malformed generated channel in an uncheckpointed task batch without an identifiable item. It cannot be assigned to a frozen text and scored incorrect. Job 23415406 completed a second attempt and retained one separate malformed response with an item ID. Its fully audited 3,400-item output remains exploratory because the first failure cannot be scored under the no-answer-quality-retry rule.

Where the models ran

  • API models: I called each provider's API between 10 and 20 September 2026, using the batch endpoints for OpenAI and Anthropic and sending one request per text for the other providers. Jev 1.13 is a model by TypeSafe that answers by choosing among a fixed set of options, and I called it via OpenRouter's Decisions API.
  • Open-weight models: each model ran on a single NVIDIA RTX PRO 6000 Blackwell GPU (96 GB of memory) on UC Davis's Hive computing cluster, using vLLM 0.26 at temperature 0. The only exception is Qwen3.8 Flash-Next, which needed two of these GPUs and a development version of vLLM.
  • Settings: reasoning is turned off for all models where this is possible, otherwise it is set to the lowest available level. API models run at the default temperature of their provider, except for the two DeepSeek models, which run at 0.1. Since every model coded every text only once, I cannot say how much the answers of a given model vary between runs. All models may return at most 256 tokens, with the exception of Jev 1.13, which returns one of the labels rather than free text.
  • Not tested: I did not run the API models with extended reasoning, which increases both cost and response time, and I did not run the largest open-weight models (Kimi K3, GLM-5.3 and MiniMax M3), since these do not run on this hardware. It is possible that the strongest configurations of these models would score higher than the top scores on this page.
Methods and limitations

Sample. For each task, I draw 100 texts by hashing task and item identifiers with the seed 20260910. All models receive the same texts, gold labels and prompts, except for Jev 1.13, which receives the prompt in its provider's choice format (i.e. with a list of the allowed labels for each output field). I only reuse earlier predictions if inputs and settings match exactly.

Scoring. For binary tasks, I use the F1 score for the positive class, for tasks with several binary labels I use the average of the per-label F1 scores, and for categorical tasks with a single label I use macro F1, which gives equal weight to each class. If a class appears neither in the gold labels nor in the predictions, its F1 is 0 by convention, which does not say anything about the model. Unusable answers are counted as incorrect, while infrastructure failures are recorded separately.

Limits. All results are based on 33 tasks. Since most tasks are taken from published data sets, some of the texts or labels may have been part of the training data of the models, which would increase their scores, and I am not able to rule this out. Before using a model at scale, researchers should validate it on labeled examples from their own task.

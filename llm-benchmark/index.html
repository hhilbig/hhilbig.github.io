Political Science LLM Benchmark

Hanno Hilbig, University of California, Davis
Results as of November 2026

FiguresHardwareMethods

On this page, I compare the performance and cost of 25 language models – 13 open-weight models as well as 12 commercial models that are accessed through an API – on text classification tasks from political science. I rely on 46 coding tasks drawn from published papers, replication archives and public data sets, covering relevance, stance, tone, events, claims and topics. For each task, every model codes the same 100 texts (50 for the six tasks with the longest texts), and I compare the labels assigned by the model to the labels assigned by human coders in the original data.

Overall, I find that differences between models are small. Gemini 4 Argon has the highest mean F1 across tasks (0.703), and the best open-weight model, Gemma 4 31B (W4A16), reaches 0.694, which is higher than seven of the 12 API models. In addition, differences of a few hundredths in the mean F1 often reverse on individual tasks – researchers who want to choose a model should therefore look at the tasks that are closest to their own application.

Not evaluated and excluded models

The models below are not ranked, either because I was not able to run them, in which case they are listed as not evaluated together with the reason, or because a run finished but violated the rules of the benchmark, in which case they are listed as excluded.

The open-weight models on this page are a selection rather than a complete list, and whether I can run a given model depends not only on its size but also on its weight files, its quantization, software support and GPU memory – if a model is missing, this does not say anything about its quality.

  • No additional candidate status has been recorded.

Results from the November 2026 release, in which I compared 43 models on 33 tasks (24 of which are also part of the 46 tasks that I use here), are still available as release refresh_20261106, although the two sets of results are not directly comparable, since the tasks, the texts and many of the models differ.

Where the models ran

  • API models: I sent the requests to the API models between 15 and 18 November 2026, through OpenRouter's batch endpoint for all models except Claude Sonnet 5, which I ran through Anthropic's batch endpoint, and DeepSeek V4.1 Flash, which has no batch endpoint and received one request per text. OpenRouter checks batch requests against the provider's content policy and refuses the whole batch if one text is flagged, so I left out the two texts that were flagged for the Anthropic models and score every model on the remaining texts.
  • Open-weight models: each model ran on a single NVIDIA RTX PRO 6000 Blackwell GPU (96 GB of memory) on UC Davis's Hive computing cluster, using vLLM 0.26 at temperature 0. The exception is Qwen3.8 Flash-Next, which ran on two GPUs with a development version of vLLM.
  • Settings: reasoning is turned off for all models where this is possible, otherwise it is set to the lowest available level. API models run at their provider's default temperature, except for the Gemini models, GLM-5.3 and DeepSeek V4.1 Flash, which run at temperature 0. Since every model coded every text only once, I cannot say how much the answers of a given model vary between runs. All models may return at most 256 tokens, with the exception of the five models that cannot turn reasoning off (Claude Opus 5.5, Claude Sonnet 5.5, GPT-6.1 Sol, Gemini 4 Argon and GLM-5.3), which may return up to 1,024 tokens (2,048 for the first 40 texts), and Gemini 3.8 Flash, which may return up to 1,024 tokens.
  • Not tested: I did not run the API models with extended reasoning, which increases both cost and response time, and I did not run the largest open-weight models (Kimi K3 and MiniMax M3), since these do not run on this hardware. It is possible that the strongest configurations of these models would score higher than the top scores on this page.
Methods and limitations

Sample. For each task, I draw 100 texts (50 for the six tasks with the longest texts) at random, stratified by task, from the texts that the open-weight models coded, and I score every model on the same 4,298 texts. All models receive the same texts, gold labels and prompts. I only reuse earlier predictions if inputs and settings match exactly.

Scoring. For binary tasks, I use the F1 score for the positive class, for tasks with several binary labels I use the average of the per-label F1 scores, and for categorical tasks with a single label I use macro F1, which gives equal weight to each class. If a class appears neither in the gold labels nor in the predictions, its F1 is 0 by convention, which does not say anything about the model. Unusable answers are counted as incorrect, while infrastructure failures are recorded separately.

Limits. All results are based on 46 tasks. Since most tasks are taken from published data sets, some of the texts or labels may have been part of the training data of the models, which would increase their scores, and I am not able to rule this out. Before using a model at scale, researchers should validate it on labeled examples from their own task.
